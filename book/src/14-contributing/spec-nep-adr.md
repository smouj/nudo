# 14.1 — Specification, NEPs and ADRs

> **Status:** Specified process  
> **Summary:** Normative rules, proposed language changes and architectural rationale are separate document classes because they answer different questions.

## Specification

Answers: **What does a conforming NUDO program mean?**

## NEP

Answers: **What language change is being proposed, why, and with what compatibility
impact?**

## ADR

Answers: **Why did the implementation or project architecture choose this approach?**

Keeping the three separate prevents design discussion from quietly turning into a
language rule and prevents old rationale from masquerading as current normative
behaviour.
