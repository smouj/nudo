# 03.3 — 解析器、无损语法与 AST

> **状态（Status）：** 已实现（IMPLEMENTED）  
> **概述（Summary）：** M2 把记号流变成了无损语法结构，能从畸形输入中恢复，并为后续语义阶段提供带类型的 AST。

## 为什么先做无损语法

无损树保留非语法内容（trivia）和每一个源码字节。这个性质对格式化器、编辑器工具
以及需要修改代码而不悄然破坏注释或排版的自动化智能体（agent）都很重要。

解析器把它作为一项被校验的性质，而不是一种意图。每一个 fixture、每一个一致性用例
以及每一个性质测试都断言：把树中记号的文本拼接起来，能够逐字节还原该文件。
`nudo check --dump-tree` 会打印这棵树，而转储之所以比它来自的文件还长，
正是因为空白和注释也在其中。

这一诚实的代价正是树呈现为这种形状的原因。`nudo-ast` 用带类型的值包裹这棵树——
一个带名字和函数体的 `Function`，一个带值的 `Binding`——当树中并不包含该部分时，
它返回空。需要确保这一点的消费者，例如一个决定是否可以改写的格式化器，
必须能够区分“这是一个函数”和“它在读到第八个记号之前看起来像一个函数”。

## 错误恢复

有用的解析器不会在第一个缺失的记号处停下。恢复点包括条目边界、分号和闭合分隔符，
使一个错误不会把文件其余部分变成噪声。

三条规则使这一点落到实处，而每一条都源自测试发现的一次失败：

* **恢复要么消耗一个记号，要么停止。** 循环的恢复就是挂起，而在用户输入上挂起就是 bug。
* **恢复在跳过之前先报告。** 早期版本会悄然跳过它无法安放的内容，`nudo check`
  随后会在它并未读懂的文件上以 `0` 退出。这比拒绝该文件更糟，因为调用方以为它已被读取。
* **一个位置，一条诊断。** 如果词法分析器已经拒绝了某个字节，解析器就不再报告
  因该字节而变得不可读的语句。一个字符产生一条消息，而修复文件的智能体只需修一个字节。

解析器无法安放的记号会保留在一个 `Error` 节点中，而不是被丢弃，
因此文件仍然可以被重新打印——包括其中出错的部分。

## 带类型的 AST

AST 为下游阶段给出语义形状（`Function`、`Call`、`Type`），
而不要求它们了解原始语法节点的细节。从语法到 AST 的转换保留跨度（span），
而一个节点的跨度恰好从它的第一个记号开始。

`nudo-ast` 中没有任何东西解析名字或检查类型：路径是一个名字列表，而不是一个引用。
那是里程碑 M3，而解析器有意对此一无所知。

## 有意缺失的东西

* 目前没有。声明处的泛型参数（`enum Outcome<T, E>`）和 `verify` 的具名操作数自 M3.1 起
  都能被解析，并且各自有一个一致性用例钉住。也没有需要补上的 `return`：
  EBNF 从未有过它，而 [NEP-0012](https://github.com/smouj/nudo/blob/main/neps/0012-early-exit.md)
  认定提前退出是块的值，而不是一条语句。一个多余的 `return` 是意外的记号，
  会产生 `NDO1001`，由 `tests/conformance/parser/0017-no-return` 钉住。
* 文法的路径使用 `::`，其列表以逗号分隔，而手册中和 `examples/` 中的若干示例
  却每行写一个 `web.search`。解析器遵循文法；那些示例声明自己是预览，
  而该语言应采用哪种拼写是一个 NEP，而不是解析器的 bug。
