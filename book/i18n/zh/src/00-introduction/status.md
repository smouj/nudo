# 00.3 — 当前项目状态

> **状态（Status）：** 已实现 / 计划中（IMPLEMENTED / PLANNED）  
> **概述（Summary）：** 仓库已有可用的编译器前端和部分类型检查支持；程序执行与效果执行约束仍属于未来里程碑。

以下状态与仓库路线图一致。“已实现”表示对应范围内存在代码和测试，
并不表示整个语言或面向用户的工作流已经完成。

| 里程碑 | 状态 | 当前可用内容 |
| --- | --- | --- |
| M0 — 仓库基础 | 已完成 | 工作区、贡献规则、CI 和文档基础设施 |
| M1 — 源模型与词法分析器 | 已完成 | 源文件、跨度、记号、词法诊断与恢复 |
| M2 — 解析器与语法树 | 已完成 | 无损语法、解析器、带类型的 AST 与语法诊断 |
| M3.0 — 语义决策门 | 已完成 | 语言实现前记录在规范和 NEP 中的已接受决定 |
| M3.1 — HIR 与名称解析 | 已完成 | HIR 降低、作用域、名称解析和 NDO2001–NDO2003 |
| M3.2 — 类型系统 | 进行中 | 已接受规则的部分类型检查器；尚未接入 CLI |
| M3.3 — 信任类型 | 部分完成 | 类型身份和已接受的 Verified 到内部类型赋值规则 |
| M4 — 解释器 | 计划中 | 第一个端到端程序和 <code>nudo run</code> |
| M5 — 效果系统 | 计划中 | 效果推断、检查和诊断；语义仍处于提案阶段 |

CLI 命令 <code>nudo check</code> 当前会读取源码，进行词法和语法分析并解析名称；
它还可以显示记号、语法树和名称解析。干净的检查结果只表示这些阶段没有报告错误，
不能证明程序类型正确、可执行或运行时安全。

类型检查 crate 覆盖基本类型与字面量、类型注解、调用、有界泛型推断、字段访问、
部分算术、Bool 条件和已接受的信任类型赋值规则。当前一致性语料独立于 CLI 覆盖这些规则。
尚未支持的规则会保持不完整，直到其语义契约准备好。

M4 与 M5 有前置依赖。M4 需要完成剩余类型系统与信任工作，并打通真实执行路径；
M5 需要这些基础，并且效果系统设计必须先被接受。路线图依据工作出口标准和一致性证据
判定里程碑完成，而不是依据日历日期。

已接受设计、提案还是计划工作。持续更新的权威状态见
