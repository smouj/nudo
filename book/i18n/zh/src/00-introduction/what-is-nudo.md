# 00.1 — 什么是 NUDO？

> **状态（Status）：** 规范已定义 / 已实现（SPECIFIED / IMPLEMENTED）
>
> **概述（Summary）：** NUDO 是一种通用语言项目，设计上显式表达信任与授权；当前实现是 pre-alpha 编译器前端。

## 一句话模型

NUDO 希望在一套类型、权限和验证体系下，连接确定性代码、人、智能体、工具与模型。

## 它要解决的问题

在许多智能体应用中，提示词是字符串，工具模式是 JSON，权限放在配置里，
预算放在供应商控制台中，验证则发生在应用代码里。每个部分都可能正常工作，
但编译器看不到它们之间的关系。

NUDO 探索把这些边界变成语言和运行时可见的结构。类型可以区分生成的数据和已验证的数据；
效果签名可以说明函数需要何种授权；运行时可以记录产生结果的输入和检查过程。
这些是设计目标，并非都已交付的功能。

## 今天已经实现的内容

当前 CLI 可以读取源文件、分词、将源码解析为无损语法树、解析名称并显示这些阶段。
HIR 和名称解析 crate 已实现。类型检查器实现了一部分已接受规则，并有自己的测试和一致性用例，
但 <code>nudo check</code> 还不会调用它。

当前工具链不能执行 NUDO 程序。目前没有解释器、效果检查器、模型供应商、
智能体运行时、工具沙箱、来源存储或 WASM 后端。
<a href="status.md">项目状态</a>和
<a href="https://github.com/smouj/nudo/blob/main/ROADMAP.md">路线图</a>
区分了已经工作的前端和计划中的子系统。

## 项目的不同之处

NUDO 把确定性软件作为默认路径，并将概率性工作限制为有明确边界的操作。
模型响应不能只因格式正确就自动成为受信任的应用数据；工具也不能只因宿主进程拥有权限
就自动获得这些权限。

编译器和运行时的设计目标，是让这些声明可以被审查，并在实现具备相应能力时执行约束。

## 它不是什么

NUDO 不是模型 SDK、提示词框架、厂商专用 DSL，也不是 Python 的新外壳。
供应商特定的请求格式属于运行时适配器；提示词组合主要属于库。
NUDO 也尚未达到生产可用状态：语言、编译器和运行时都不完整，并会依照规范流程继续演进。

## 事实来源

规范定义语言。已接受的 NEP 修订规范。测试固定可观察的实现行为。
本书解释动机和状态，但不会私自决定尚未解决的语言问题。
