# 02.2 — 表达式与优先级

> **状态（Status）：** 已实现 / 规范已定义 / 计划中（IMPLEMENTED / SPECIFIED / PLANNED）
> **摘要：** 解析器实现了文法；类型检查器也会检查运算符、`if` 分支和带类型的枚举 `match`。索引语义仍待决定。

优先级不是格式细节。`a + b * c` 在每个符合规范的实现中都必须只有一个含义，
而解析器正是产生这种形状：`1 + 2 * 3` 的树中，乘法是内层节点，加法位于其上。

这些问题不再是未决问题。它们作为一条文法层级链，只在一处陈述——
[`grammar/nudo.ebnf`](https://github.com/smouj/nudo/blob/main/grammar/nudo.ebnf)——
以完全相同的内容复制到描述它的两份文档中，并由
[`scripts/check-grammar.py`](https://github.com/smouj/nudo/blob/main/scripts/check-grammar.py)
机械校验：

- 后缀运算的结合比一元运算符更紧，并且可以链式连接，因此 `a.b(c)[d]` 是一个表达式；
- 乘法与除法的结合比加法与减法更紧，二者均为左结合；
- 比较**不**链式连接：`a < b < c` 是语法错误，而不是 `(a < b) < c`；比较用 `&&` 组合；
- 布尔运算符有固定优先级，`||` 最松；
- 不存在赋值层级，因为 NUDO 是否拥有可变绑定本身尚未决定。现在写出该层级，
  等于为了填补图中的空缺而发明一项语言特性；
- `ask`、`verify` 和 `delegate` 是主要表达式而非运算符，这正是 `verify draft with V`
  可解析的原因：`with` 不是运算符，也没有任何后缀形式以它开头。

让这一切可校验而非仅停留在愿望上的规则是**禁止左递归**。递归下降解析器无法处理
能推导出以自身开头的形式的产生式，而这份文法的最初版本中有四个这样的产生式。
现在它是一个构建失败，而不是一个尚未发生的发现。

格式化器应输出足以保留含义的语法，而不依赖人的直觉。

## 运算符与 `if` 的核心规则

[NEP-0017](https://github.com/smouj/nudo/blob/main/neps/0017-boolean-comparison-conditionals.md)
定义了运算符的类型范围和条件表达式的结果类型：

- `!`、`&&` 和 `||` 使用 `Bool`；`&&` 与 `||` 从左到右短路求值。操作数类型无效时，
  错误 `NDO2018` 指向运算符。
- 相等比较只接受 `Int`、`Float`、`Bool` 或 `Text` 的相同基本类型视图。大小比较
  只支持相同的 `Int` 或 `Float`。没有数值转换或用户定义的运算符重载。已接受的
  `Verified<T>` 到 `T` 视图也适用于运算符输入。
- `Float` 比较遵循 IEEE-754：NaN 与自身不相等且不可排序；正零与负零相等。
- `if` 条件必须是 `Bool`。存在 `else` 时，已知期望类型会检查两个分支；否则两个
  分支的类型必须完全相同。不一致时，`NDO2019` 指向 `else` 分支。
- 没有 `else` 的 `if` 类型为 `Unit`，其 `then` 分支也必须是 `Unit`。

运行时不会执行短路跳过的操作数或未选中的分支。静态效果检查仍会考虑它们，确保
声明对任何输入都有效。

## 枚举的类型化匹配

[NEP-0020](https://github.com/smouj/nudo/blob/main/neps/0020-typed-enum-matching.md)
为用户定义的枚举和内置的 `Result<T, E>` 定义了 `match`。每个分支都要指定一个已声明的
变体，或使用 `_`；payload 按位置绑定为声明类型，并先替换泛型参数。必须覆盖所有变体，
除非一个可达的通配符覆盖剩余情况。未知名称是错误，绝不会成为绑定。没有期望结果类型时，
所有分支的类型必须完全相同；有期望类型时，每个分支按普通赋值规则检查。类型检查器会
报告模式、覆盖和分支错误，同时继续检查每个分支体。

```nudo
fn describe(value: Result<Int, Text>) -> Text {
    match value {
        Ok(number) => "success"
        Err(reason) => reason
    }
}
```

解析器和类型检查器的一致性用例覆盖泛型 payload、`Result`、通配符、无效模式、错误恢复和
分支类型。类型检查器尚未接入 `nudo check`。
