# 02.2 — 表达式与优先级

> **状态（Status）：** 规范已定义（SPECIFIED）  
> **概要：** 优先级、结合性以及禁止左递归都已被确定并机械校验。实现它们的解析器属于 M2。

优先级不是格式细节。`a + b * c` 在每个符合规范的实现中都必须只有一个含义。

这些问题不再是未决问题。它们作为一条文法层级链，只在一处陈述——
[`grammar/nudo.ebnf`](https://github.com/smouj/nudo/blob/main/grammar/nudo.ebnf)——
以完全相同的内容复制到描述它的两份文档中，并由
[`scripts/check-grammar.py`](https://github.com/smouj/nudo/blob/main/scripts/check-grammar.py)
机械校验：

- 后缀运算的结合比一元运算符更紧，并且可以链式连接，因此 `a.b(c)[d]` 是一个表达式；
- 乘法与除法的结合比加法与减法更紧，二者均为左结合；
- 比较**不**链式连接：`a < b < c` 是语法错误，而不是 `(a < b) < c`；比较用 `&&` 组合；
- 布尔运算符有固定优先级，`||` 最松；
- 不存在赋值层级，因为 NUDO 是否拥有可变绑定本身尚未决定。现在写出该层级，
  等于为了填补图中的空缺而发明一项语言特性；
- `ask`、`verify` 和 `delegate` 是主要表达式而非运算符，这正是 `verify draft with V`
  可解析的原因：`with` 不是运算符，也没有任何后缀形式以它开头。

让这一切可校验而非仅停留在愿望上的规则是**禁止左递归**。递归下降解析器无法处理
能推导出以自身开头的形式的产生式，而这份文法的最初版本中有四个这样的产生式。
现在它是一个构建失败，而不是一个尚未发生的发现。

格式化器应输出足以保留含义的语法，而不依赖人的直觉。
