# 08.2 — 前端基准测试

> **状态（Status）：** 已实现 / 计划中（IMPLEMENTED / PLANNED）
>
> **概述（Summary）：** NUDO 提供一套小型、可复现的前端基准测试；结果描述记录的工作负载和主机，不代表通用速度评级。

基准程序测量当前已经存在的编译器阶段。解释器和 <code>nudo run</code>
尚不存在，因此它不测量 NUDO 程序的执行时间。

## 工作负载与阶段边界

基准套件会生成四种确定性的合成输入：函数声明、let 绑定、文本字面量和大量注释的源码。
每种输入都会经过四个阶段测量，共十六行：

| 阶段 | 计时工作 |
| --- | --- |
| 词法分析 | 对已登记的源码文件进行分词 |
| 解析 | 分词并调用公开解析器完成解析 |
| HIR | 降低预先构建的语法树 |
| 类型检查 | 检查预先构建的 HIR |

解析必须先有记号流，因此其测量包含词法分析。HIR 降低和类型检查会在计时开始前准备输入，
所以报告值只计对应阶段。工作负载刻意保持小型且合成，不能代表语言的所有功能或完整应用程序。

类型检查阶段的单位是表达式类型表的长度，其中也包括没有类型的槽位。它不统计执行了多少条语义规则，
也不统计成功检查了多少个表达式。单位数相同并不能证明语义工作量相同。

## 结果记录的内容

每次运行会记录源码修订和工作区是否有未提交改动、Rust 编译器、操作系统、架构、可用时的 CPU 描述、
迭代次数、输入字节数、输出单位以及计时统计。报告包含最小值、中位数、第 95 百分位数和平均值；
词法分析与解析行还会报告吞吐量。项目目前没有统一参考 baseline，CI 也没有自动性能门槛。

## 比较结果

请使用 release 构建。比较时保持工作负载、阶段边界、迭代设置和编译器工具链一致，
并在同一台低负载机器上运行两个版本，重复测量，并将 JSON 报告与待审查的改动一同保存。
单次比较只是调查信号；在把时间差归因于代码之前应重复测量。

PR #31 改变了类型检查器所覆盖的语义。改动前后的类型检查测量，即使源码和表达式类型表计数相同，
也可能代表两个实现完成了不同的工作。单靠这些结果无法证明在等量工作下性能回退或提升。

## 跨机器测量

某台电脑的结果是该电脑和该设置下的测量点。它可以辅助粗略规划，但仅凭时钟频率、核心数或 CPU 型号，
无法可靠地换算到另一颗 CPU。微架构、内存和缓存、持续功率限制、操作系统调度、编译器版本及后台负载，
都可能以不同幅度影响各个阶段。

要估算目标机器上的表现，请在目标机器上用相同提交和工作负载运行基准，记录元数据并重复测量。
如果无法做到，请把估算标注为“粗略外推”，并列出假设与不确定性；不要把它写成基准测量结果。
