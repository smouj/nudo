# 08.1 — 工具链与 CLI

> **状态（Status）：** 已实现 / 计划中（IMPLEMENTED / PLANNED）  
> **概述（Summary）：** 当前 <code>nudo</code> 命令可以检查源码、语法和名称；类型检查、执行、效果和更广泛的工具链仍属于未来工作。

## 已实现的命令

~~~sh
nudo check path/to/file.nudo
nudo check --dump-tokens path/to/file.nudo
nudo check --dump-tree path/to/file.nudo
nudo check --dump-resolutions path/to/file.nudo
nudo --version
nudo --help
~~~

check 命令会加载一个或多个源文件，进行词法和语法分析，把已接受的语法降低到 HIR，
解析名称并报告词法、语法及名称解析诊断。它还可以生成纯文本或面向 CI 的报告。

该命令的范围到名称解析为止。检查结果干净不代表程序类型正确或可执行。
部分类型检查器作为单独 crate 存在，并由单元测试和一致性用例覆盖；CLI 尚未调用它。
目前没有 <code>nudo run</code>、<code>nudo build</code>、REPL、格式化器、语言服务器或包管理器。

退出码是稳定的：0 表示已实现阶段没有错误诊断；1 表示至少报告一项错误；
2 表示使用方式或输入错误，或命令尚未实现。

## 前端性能测量

独立的 <code>nudo-bench</code> 程序测量四种确定性合成输入在四个阶段的表现：
词法分析、解析、HIR 降低和类型检查，共十六行。后续阶段的源码或 HIR 准备工作
发生在计时区间之外；公开解析器需要记号，因此 parse 计入词法处理。

类型检查阶段报告表达式类型表的长度，其中包括没有类型的槽位。
它并不统计实际执行了多少语义规则或成功检查了多少表达式。相同计数不能证明工作量相同。

{{#include ../diagrams/benchmark-portability.svg}}

*观察到的用时取决于记录的整套环境。无法仅根据 MHz 或核心数可靠推算另一台硬件的用时。*

每次运行会记录 commit、工作区是否有未提交改动、Rust 版本、操作系统、架构、
可用时的 CPU 型号、输入大小、迭代次数和计时统计。仓库目前没有项目级参考 baseline，
CI 也没有自动性能门槛。

为了进行有意义的比较，请以 release 模式构建，在相同机器、相近的低负载条件下，
使用相同工作负载、阶段边界和迭代设置测量两个版本。请重复运行。
超过阈值只代表需要调查的信号；单次样本不能证明性能回退。

一台电脑的结果只描述该电脑和工作负载。它可用于粗略规划，但不能可靠转换为另一台 CPU 的结果。
微架构、内存与缓存、持续功率限制、操作系统调度、编译器版本和后台负载都可能以不同方式影响各阶段。

需要估算目标设备时，应在该设备上用相同 commit、工作负载和设置运行基准，并记录元数据、多次重复。
如果无法做到，应明确标注“粗略外推”，并写出假设和不确定性；不要将外推写成基准结果。

该套件只测量编译器前端。由于解释器和运行命令尚不存在，它无法报告解释器启动、
端到端程序执行、智能体/模型调用或峰值内存。
