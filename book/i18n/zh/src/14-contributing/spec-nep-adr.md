# 14.1 — 规范、NEP 与 ADR

> **状态（Status）：** 规范已定义的流程（SPECIFIED process）  
> **概述（Summary）：** 规范性规则、提案的语言变更和架构理由属于不同的文档类别，因为它们回答不同的问题。

## 规范（Specification）

回答：**一个符合规范的 NUDO 程序意味着什么？**

## NEP

回答：**提出了什么语言变更、为什么提出，以及兼容性影响是什么？**

## ADR

回答：**实现或项目架构为什么选择了这种做法？**

把三者分开，可以防止设计讨论悄然变成语言规则，也可以防止旧的理由伪装成当前的规范行为。
