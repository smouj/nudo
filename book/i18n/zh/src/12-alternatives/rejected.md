# 12.1 — 被有意拒绝的替代方案

> **状态（Status）：** 历史 / 设计理由（Historical / Design rationale）  
> **概述（Summary）：** 有几种更简单的做法在应用中很有用，但不满足 NUDO 的目标：让信任与授权成为语言可见的。

| 替代方案 | 为什么它不足以作为语言模型 |
| --- | --- |
| 把提示词当作普通字符串 | 编译器无法从散文式文本中推断信任或授权。 |
| 权限只存在于部署配置中 | 源码层面的调用无法对照授予路径进行检查。 |
| `verified: Bool` 标记 | 安全性变成可选的运行时约定。 |
| 供应商特定的关键字 | 把语言含义耦合到厂商 API 上。 |
| 无界的智能体循环 | 使授权、预算和终止难以审查。 |
| 仅日志式的来源 | 事后重建证据，可能丢失值的血缘。 |

这些技术仍然可以出现在运行时适配器（adapter）或库中。此处的拒绝意味着
“不作为语言的语义基础”，而不是“永远无用”。
