# 04.2 — `Generated<T>` 与 `Verified<T>`

> **状态（Status）：** 提案中（PROPOSED）  
> **概述（Summary）：** 信任类型（trust type）意在阻止概率性输出通过隐式转换变成受信任的应用数据。


{{#include ../diagrams/trust-flow.svg}}

*模型输出只有经过一个显式步骤，才成为已验证的值。*

## 为什么不是 `T`？

如果模型直接返回一个 `Article`，关于该值如何产生的来源信息就会从类型边界上消失。

## 为什么不是 `Result<T, E>`？

`Result` 可以表示一个操作的成功/失败。它不表示一个成功值的信任状态。
一个被完美解析的模型响应仍然可以是未验证的。

## 为什么不是一个布尔标记？

```text
ModelOutput<T> { value: T, verified: Bool }
```

这把规则推入运行时约定。调用方可能忘记检查该标记。不同的类型让检查器
可以把缺失的转换变成无法忽视的错误。

## 必须回答的设计问题

在稳定化之前，NUDO 必须规定验证器失败类型、组合、来源保留、序列化边界，
以及与泛型和模式匹配的交互。
