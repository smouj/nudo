# 05.2 — タスク、ツール、モデル

> **ステータス:** 提案中 (Proposed)  
> **概要:** NUDO は目的、エフェクトを持つツール、モデルプロバイダーを分離し、単一のベンダーを言語に焼き込むことなく自律性を境界付けることができます。


{{#include ../diagrams/interfaces.svg}}

*四つの宣言と、それぞれを制約するもの。*

## タスク

タスクは、目的、期待される結果、制限、トレーサビリティを備えた自律的な作業の単位です。通常の関数呼び出しとは異なり、タスクは作業がどのように行われたかについてのエビデンスを生成することが期待されます。

## ツール

ツールはコードと外部のケイパビリティを橋渡しします。ネットワーク、ファイルシステム、シェル、Git、あるいは別のサービスです。したがってツールの呼び出しはエフェクトを持ち、ケイパビリティによって制限されます。

## モデル

モデルはプロバイダー中立なランタイムインターフェースです。プロバイダーの API フィールドや認証が、NUDO プログラムの意味を変えるべきではありません。
