# 04.1 — 型システムの基礎

> **Status:** 実装済み (IMPLEMENTED) / 仕様策定済み (SPECIFIED) / 計画中 (PLANNED)
>
> **Summary:** NUDO には採用済み型規則を部分的に実装したチェッカーがあります。完全な型システムは開発中で、CLI の <code>check</code> コマンドにはまだ組み込まれていません。

型システムは言語に関する章と採用済み NEP で仕様化されています。Rust crate <code>nudo-typeck</code> は対応範囲を拡大中で、ソーステキストではなく HIR を受け取ります。テストと適合性ケースが実装済み規則を検証します。CLI はまだチェッカーを呼び出しません。

## 現在のチェッカーが実装する規則

| 規則 | 現在の動作 |
| --- | --- |
| プリミティブ型とリテラル型 | <code>Int</code>、<code>Float</code>、<code>Bool</code>、<code>Text</code>、<code>Unit</code> を表現 |
| 整数リテラルの範囲 | <code>Int::MAX</code> を受け入れます。<code>2^63</code> は <code>Int::MIN</code> を表す単項 <code>-</code> の直接のオペランドとしてのみ受け入れ、それより大きい値やその他の無効な値は <code>NDO2010</code> になります |
| 注釈と関数シグネチャー | 値を記述された型と比較し、関数型と呼び出しを検査 |
| 関数の結果 | 結果型注釈を省略すると <code>Unit</code>。値を返す関数は結果型を宣言し、本文の不一致には <code>NDO2004</code> を使用 |
| 呼び出し | 引数の個数には <code>NDO2005</code>、互換性のない引数には <code>NDO2004</code>、呼び出せない値には <code>NDO2006</code> |
| ジェネリック呼び出し | 引数およびすでに判明している期待戻り値型からソース順に推論。推論できない型パラメーターは <code>NDO2008</code>、関数シグネチャーで使われない型パラメーターは <code>NDO2009</code> で診断 |
| 名前付き型 | 型引数の個数には <code>NDO2017</code> を使い、nominal identity と対応済みフィールドアクセスを検査 |
| 演算子 | 算術は同じ数値ビューを要求し、<code>%</code> は Int のみ。論理演算子は <code>Bool</code>、等価比較は一致するプリミティブビュー、順序比較は一致する <code>Int</code> または <code>Float</code> を使用。無効な型は <code>NDO2018</code> |
| 条件式 | <code>if</code> の条件は <code>Bool</code>。期待型があれば両分岐を検査し、なければ型が完全一致する必要があります。<code>else</code> がなければ結果と <code>then</code> 分岐は <code>Unit</code> です。文脈のない不一致は <code>NDO2019</code> |
| 信頼型の代入 | 組み込みの <code>Verified&lt;T&gt;</code> は、対応する位置で <code>T</code> が期待される場合に使用可能 |

ジェネリック推論には意図的な制限があります。プログラム全体の型を解決せず、ローカル束縛を一般化せず、未解決パラメーターを推測もしません。ジェネリック引数は invariant のままで、数値変換は暗黙には行われません。[NEP-0015](https://github.com/smouj/nudo/blob/main/neps/0015-uninferable-generic-parameters.md) はこの境界を明示します。十分な情報がないジェネリック呼び出しは <code>NDO2008</code>、関数シグネチャーに現れない型パラメーターは <code>NDO2009</code> で報告します。関数値を呼び出す場合、外側の型パラメーターは固定されたままです。既存のエラーに依存する診断だけを抑制して、連鎖を防ぎます。

## 未完成の規則

シーケンスのインデックスと実行時の境界動作、nominal construction、<code>match</code>、<code>Result&lt;T, E&gt;</code> の match は未対応です。検証器の実行と来歴、エージェント、タスク、ツールもこのチェッカーには実装されていません。

これらの不足は意図的です。意味論と診断の契約が採用されて初めて、その規則を実装済みとします。ロードマップと仕様は、準備できた作業と未解決の判断を記録します。

## CLI の check が成功した場合の意味

<code>nudo check</code> は字句、構文、名前解決の段階を実行します。部分的な型チェッカーはこのコマンドに接続されていないため、CLI が成功してもすべての型規則を通過したとは言えません。現状チェッカーは、専用テストと型検査の適合性コーパスで検証されています。
