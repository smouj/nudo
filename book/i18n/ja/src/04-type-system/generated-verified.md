# 04.2 — `Generated<T>` と `Verified<T>`

> **ステータス:** 提案中 (Proposed)  
> **概要:** トラスト型は、確率的な出力が暗黙の変換を通じて信頼されたアプリケーションデータになることを防ぐことを意図しています。


{{#include ../diagrams/trust-flow.svg}}

*モデル出力は、明示的な段階を経てのみ検証された値になります。*

## なぜ `T` ではないのか

モデルが `Article` を直接返すなら、その値がどのように生成されたかという来歴が型の境界から消えます。

## なぜ `Result<T, E>` ではないのか

`Result` は操作の成功・失敗を表現できますが、成功した値のトラスト状態を表現するものではありません。完全にパースされたモデル応答であっても、未検証であり得ます。

## なぜブール値のフラグではないのか

```text
ModelOutput<T> { value: T, verified: Bool }
```

これは規則をランタイムの慣習へと押しやります。呼び出し側はフラグの検査を忘れられます。別々の型であれば、チェッカーは欠落した遷移を無視できないものにできます。

## 必須の設計上の問い

安定化の前に、NUDO は検証失敗の型、合成、来歴の保持、シリアライズの境界、ジェネリクスやパターンマッチングとの相互作用を規定しなければなりません。
