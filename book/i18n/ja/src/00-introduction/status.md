# 00.3 — 現在のプロジェクト状況

> **Status:** 実装済み (IMPLEMENTED) / 計画中 (PLANNED)
> **Summary:** リポジトリには動作するコンパイラーフロントエンドと部分的な型検査機能があります。プログラム実行とエフェクト検査は今後のマイルストーンです。

以下の状況はリポジトリのロードマップを反映しています。「実装済み」とは、示された範囲のコードとテストが存在することを意味します。言語全体やユーザー向けのワークフローが完成したという意味ではありません。

| マイルストーン | 状況 | 利用できる機能 |
| --- | --- | --- |
| M0 — リポジトリの基盤 | 完了 | ワークスペース、コントリビューション規則、CI、ドキュメント基盤 |
| M1 — ソースモデルと lexer | 完了 | ソースファイル、span、token、字句診断、エラー回復 |
| M2 — parser と構文木 | 完了 | 損失のない構文、parser、型付き AST、構文診断 |
| M3.0 — 意味論上の判断 | 完了 | 採用済みの判断を仕様と NEP に記録 |
| M3.1 — HIR と名前解決 | 完了 | HIR への lowering、スコープ、名前解決、NDO2001–NDO2003 |
| M3.2 — 型システム | 進行中 | enum と <code>Result</code> の型付き match を含む、採用済み規則の部分的な型チェッカー。CLI から呼び出し |
| M3.3 — 信頼型 | 一部完了 | 型の同一性と、Verified から内部型への採用済み代入規則 |
| M4 — インタープリター | 計画中 | 最初のエンドツーエンドプログラムと <code>nudo run</code> |
| M5 — エフェクトシステム | 計画中 | エフェクト推論、検査、診断。意味論はまだ提案段階 |

CLI コマンド <code>nudo check</code> はソースを読み込み、字句解析と構文解析を行い、名前を解決して、実装済みの採用済み型規則を検査します。token、構文木、名前解決の結果を表示できます。エラーのない実行とは、実装済みの段階でエラーが報告されなかったことを示します。未対応の規則、実行可能性、実行時の安全性は保証しません。

型チェッカーの crate は、プリミティブ型とリテラル型、注釈、呼び出し、制約されたジェネリック推論、フィールドアクセス、一部の算術演算、Bool 条件、enum と <code>Result</code> の型付き match、採用済みの信頼型代入を扱います。現在の適合性コーパスも、これらの規則を CLI とは独立に検証します。未対応の規則は、意味論上の契約が整うまで意図的に未完成のままです。

M4 と M5 には依存関係があります。M4 には、残りの型と信頼に関する作業、および実際の実行経路が必要です。M5 にはそれらの基礎と、採用済みのエフェクトシステム設計が必要です。ロードマップは完了を日付ではなく、動作する終了条件と適合性の証拠で定義します。

## ステータスラベルが重要な理由

洗練された例は、提供済みの機能のように見えることがあります。そのため各章で、実装済みの動作、採用済みの設計、提案、計画中の作業のどれを説明しているかを示します。<a href="https://github.com/smouj/nudo/blob/main/ROADMAP.md">ロードマップ</a>が、随時更新される正式な状況記録です。
