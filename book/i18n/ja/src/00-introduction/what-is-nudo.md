# 00.1 — NUDO とは何か

> **Status:** 仕様策定済み (SPECIFIED) / 実装済み (IMPLEMENTED)
>
> **Summary:** NUDO は信頼と権限を明示する設計を持つ汎用プログラミング言語プロジェクトです。現在の実装はフロントエンドが動作する pre-alpha のコンパイラーです。

## 一文で表すモデル

NUDO は、決定論的なコード、人間、エージェント、ツール、モデルを、共通の型・権限・検証システムで結びつけることを目指します。

## 解決を目指す課題

多くのエージェントアプリケーションでは、prompt は文字列、ツールの schema は JSON、権限は設定ファイル、予算はプロバイダーのコンソール、検証はアプリケーションコードに置かれています。それぞれは動作しても、コンパイラーから相互の関係は見えません。

NUDO は、その境界を言語と runtime に可視化する方法を探ります。型によって生成データと検証済みデータを区別できます。effect signature によって関数が必要とする権限を示せるかもしれません。runtime は結果を生んだ入力と検査を記録できるかもしれません。これらは設計目標であり、すべてがすでに利用可能な機能ではありません。

## 現在あるもの

CLI はソースファイルを読み込み、token 化し、損失のない構文木に parse し、名前を解決して、実装済みの採用済み型規則を検査できます。HIR、名前解決、部分的な型チェッカーの crate は実装済みです。型チェッカーには独自のテストと適合性ケースもあります。

現在の toolchain は NUDO プログラムを実行しません。インタープリター、effect checker、モデルプロバイダー、エージェント runtime、ツール sandbox、provenance store、WASM backend はまだありません。<a href="status.md">プロジェクト状況</a>と<a href="https://github.com/smouj/nudo/blob/main/ROADMAP.md">ロードマップ</a>では、動作するフロントエンドと計画中のサブシステムを区別しています。

## プロジェクトの特徴

NUDO は決定論的ソフトウェアを通常の経路とし、確率的な処理を、信頼境界が見える制限付きの操作として扱います。モデルの応答は、形が合っているというだけで信頼済みアプリケーションデータになってはいけません。ホストプロセスが権限を持つというだけで、ツールに権限が与えられてはいけません。

コンパイラーと runtime は、これらの主張をレビュー可能にし、実装が存在する範囲で強制することを目指します。

## 該当しないもの

NUDO はモデル SDK、prompt framework、ベンダー固有 DSL、Python の新しい皮ではありません。プロバイダー固有のリクエスト形式は runtime adapter に置き、prompt の構成は通常ライブラリーに任せます。また NUDO は本番利用可能ではありません。言語、コンパイラー、runtime は未完成で、仕様策定プロセスを通じて変更される可能性があります。

## 正式な情報源

言語は仕様が定義します。採用済み NEP が仕様を改訂します。テストは実装の観測可能な動作を固定します。本書は背景と状況を説明しますが、未解決の言語上の問題を暗黙に決定することはありません。
