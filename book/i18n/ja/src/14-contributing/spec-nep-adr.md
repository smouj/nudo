# 14.1 — 仕様、NEP、ADR

> **ステータス:** 仕様化済みのプロセス (Specified process)  
> **概要:** 規範的な規則、提案された言語変更、アーキテクチャの根拠は、異なる問いに答えるため、別々の文書クラスです。

## 仕様

答える問い: **適合する NUDO プログラムは何を意味するか。**

## NEP

答える問い: **どのような言語変更が提案されているのか、なぜか、互換性への影響は何か。**

## ADR

答える問い: **実装またはプロジェクトのアーキテクチャが、なぜこのアプローチを選んだのか。**

三者を分離しておくことで、設計の議論が静かに言語の規則へと変わることを防ぎ、古い根拠が現在の規範的挙動を装うことを防ぎます。
