# 15.1 — マイルストーンと証拠

> **Status:** 歴史 (HISTORICAL) / 継続更新
> **Summary:** NUDO は証拠に基づくマイルストーンで進捗を測ります。M3 は引き続き進行中で、M5 に必要なインタープリターとエフェクトシステムは計画中です。

ロードマップでは日付ではなく、終了条件と適合性の証拠で進捗を測ります。このページは M5 までの道筋を要約します。リポジトリのロードマップが正式な情報源です。

{{#include ../diagrams/status.svg}}

| マイルストーン | 状況 | 完了を示す証拠 |
| --- | --- | --- |
| M0 — リポジトリの基盤 | 完了 | 新しい checkout を build、check、review できる |
| M1 — ソースモデルと lexer | 完了 | 決定論的 token、診断、エラー回復 |
| M2 — parser と構文木 | 完了 | 損失のない parse、回復、適合性ケース |
| M3.0 — 意味論上の判断 | 完了 | 基本的な型システム判断を実装前に記録 |
| M3.1 — HIR と名前解決 | 完了 | 解決済み HIR と安定した名前診断 |
| M3.2 — 基本型システム | 進行中 | 採用済み規則を適合性の証拠とともに段階的に追加 |
| M3.3 — 信頼型 | 一部完了 | 型 identity と Verified の代入が存在。verify と provenance は未対応 |
| M4 — インタープリター | 計画中 | 例のプログラムが <code>nudo run</code> で42を計算して出力 |
| M5 — エフェクトシステム | 計画中 | エフェクトなしの関数からのエフェクト呼び出しを、経路を示して拒否 |

M4 と M5 は、番号が続く交換可能な作業ではありません。M4 の終了条件は、ソースから出力までの実際の実行経路です。M5 は型と信頼の基礎に依存し、採用済みのエフェクト意味論を必要とします。Draft の提案は実装契約にできません。

## マイルストーンが守るもの

この順序により、洗練された demo がコンパイラーの保証の代わりになることを防ぎます。M5 を完了とする前に、先行する型と信頼の条件を満たし、M4 で文書化された例を実行し、エフェクトシステムの意味論を採用し、診断と適合性ケースで終了条件を実証する必要があります。

ロードマップは M5 の達成日を約束しません。報告する進捗は、build でき、規定されたテストに合格した範囲に基づきます。
