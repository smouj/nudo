# 10.1 — リポジトリのアーキテクチャ

> **ステータス:** 実装済みの基盤 (Implemented foundation)  
> **概要:** モノレポは、概念上のクレート境界を保ちながら、仕様、コンパイラ、ランタイム、ツール群の進化を一つの監査可能な履歴に保ちます。

ワークスペースは、コンパイラの段階、ランタイムサービス、共有基盤クレート、CLI、ツール群、バックエンドを分離します。これにより所有関係が可視になりますが、pre-alpha のクレート境界は改訂可能なままでいるべきです。

プレースホルダーのクレートはロードマップ上の目印であり、その公開 API が準備できた証拠ではありません。実装は、経験がより良い境界を示したときに、内部の単位を統合あるいは分割できるようにすべきです。
