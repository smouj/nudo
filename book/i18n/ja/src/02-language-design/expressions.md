# 02.2 — 式と優先順位

> **ステータス:** 仕様化済み (SPECIFIED)  
> **概要:** 優先順位、結合性、左再帰の禁止は決定済みで、機械的に検査されています。それを実装するパーサーが M2 です。

優先順位は書式の些事ではありません。`a + b * c` は、準拠するどの実装でも
ただ一つの意味を持たなければなりません。

これらはもう未解決の問いではありません。文法レベルの連鎖として
[`grammar/nudo.ebnf`](https://github.com/smouj/nudo/blob/main/grammar/nudo.ebnf)
に一度だけ記述され、それを説明する二つの文書に同一の内容で複製され、
[`scripts/check-grammar.py`](https://github.com/smouj/nudo/blob/main/scripts/check-grammar.py)
によって機械的に検査されています。

- 後置演算は単項演算子より強く結合し、連鎖するため、`a.b(c)[d]` は一つの式です。
- 乗算と除算は加算と減算より強く結合し、どちらも左結合です。
- 比較は**連鎖しません**。`a < b < c` は `(a < b) < c` ではなく構文エラーであり、
  比較は `&&` で組み合わせます。
- ブール演算子の優先順位は固定で、`||` が最も弱くなります。
- 代入のレベルは存在しません。NUDO に可変の束縛があるかどうか自体が未決定だからです。
  図の隙間を埋めるために今このレベルを書くことは、言語機能を発明することになります。
- `ask`、`verify`、`delegate` は演算子ではなく主要式です。これが `verify draft with V`
  を解析可能にしています。`with` は演算子ではなく、`with` で始まる後置形式はないからです。

これを理念ではなく検査可能にしている規則は、**左再帰の禁止**です。再帰下降パーサーは、
自分自身で始まる形式を導出する生成規則を扱えません。この文法の最初の版には四つありました。
それは今やビルドの失敗であり、これから起きる発見ではありません。
