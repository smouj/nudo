# 02.1 — 文法と構文の規律

> **ステータス:** 実装済み (IMPLEMENTED) / 提案中 (PROPOSED)  
> **概要:** 文法はソーステキストとパーサーの間の契約であり、パーサーによって実装され、チェッカーによって強制されます。暫定的なエージェント構文は、受理されるまで目に見えて暫定的であり続けます。

## 小さな構文、強い意味

NUDO の設計目標は、AI の概念ごとにキーワードを発明することではありません。新しい形式はそれぞれ解析、ツール、整形、学習、互換性に影響するため、構文は高くつきます。

## パーサーからの圧力

再帰下降パーサーは、式の文法が優先順位について明示的で、左再帰を避けるときに最もよく機能します。堅牢な式の階層は、概念的には次のように構成されるべきです。

```text
logical-or
  → logical-and
  → equality
  → comparison
  → additive
  → multiplicative
  → unary
  → postfix
  → primary
```

後置 (postfix) の解析は、呼び出し、フィールドアクセス、インデックス参照が自然に組み合わさる場所です。

## 文脈依存語と予約語

字句解析器が予約として扱うべきなのは、実際に予約トークンとして受理される語だけです。`agent`、`task`、`ask`、`verify` のような将来の構文は、ツールがそれに依存する前に NEP レベルの決定を必要とします。
