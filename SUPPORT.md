# Support

## The short version

NUDO is pre-alpha. There is no support commitment, no stable release and no
guarantee that an answer exists. What there is: a maintainer who reads the
issues, and a small number of contributors who know the code.

## Where to ask

| You want to | Use |
| ----------- | --- |
| Ask a question, or discuss an idea that is not yet a proposal | [Discussions](https://github.com/smouj/nudo/discussions) |
| Propose a language change | [Discussions](https://github.com/smouj/nudo/discussions) → *Language design*, then a [NEP](neps/README.md) |
| Report something that is broken | [Issues](https://github.com/smouj/nudo/issues/new/choose), using the forms |
| Report a vulnerability | [`SECURITY.md`](SECURITY.md) — never a public issue |
| Contribute a change | [`CONTRIBUTING.md`](CONTRIBUTING.md) and [`AGENTS.md`](AGENTS.md) |

## Before you ask

* `nudo --help` lists exactly which commands work and which are planned.
* `ROADMAP.md` says which milestone a feature belongs to. "This is not
  implemented" is usually a roadmap question, and the roadmap answers it.
* If you are an agent, read [`AGENTS.md`](AGENTS.md) first. Most questions that
  arrive from agents are answered there.

## What support is not

* NUDO will not be made to run your project in its current state; nothing runs
  yet beyond lexing.
* There is no commercial support, no paid tier and no priority queue.
* A question that the documentation should have answered is a documentation
  bug. Report it as one — that is a genuinely useful contribution.

## Response expectations

Best effort. Issues and discussions are usually read within a week; complex
design questions can take longer, and silence is not rejection. If something is
time-critical for you, say so in the message and explain why.
